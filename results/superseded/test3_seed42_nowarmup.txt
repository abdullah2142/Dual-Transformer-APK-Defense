WHY IT WAS DISCARDED
--------------------
graphcodebert-train-text-only.ipynb, which produced Table 1's checkpoint, uses
num_warmup_steps=int(total_steps * 0.1). This notebook passed 0. Everything else
matched -- model class, optimizer, drop_last, AMP, gradient clipping, sampler,
sequence lengths, partition.

Seed 42 was supposed to reproduce Table 1's 88.2692% and came back 0.2642pp low.

WHAT IT IS STILL EVIDENCE FOR
-----------------------------
Warmup is not cosmetic on this task. Removing it changed the whole trajectory:

  with 10% warmup (Table 1) : 86.45 -> 87.39 -> 88.84 -> 89.19* -> 89.04 -> 88.86
  with no warmup (this run) : 87.59 -> 88.38 -> 88.44 -> 88.92 -> 88.94* -> 88.60 -> 88.84

No warmup starts the LR at full value, so epoch 1 is better (87.59 vs 86.45) but
the peak is worse (88.94 vs 89.19) and arrives a epoch later. Final test accuracy
falls 0.2642pp.

That number is worth keeping. A single unmatched schedule detail moves accuracy by
0.26pp, which is comparable to the 0.410pp DFG delta that PAPER.md 3.2 reports as
the one statistically significant within-backbone result. It is an independent
instance of the point Section VI already makes about protocol sensitivity, and it
argues for measuring the seed noise floor rather than assuming it is small.

Superseded by the re-run with warmup restored.
